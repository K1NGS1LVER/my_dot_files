# Archived learned fixes (cold log — read on demand)

Bullets moved out of CLAUDE.md so each agent session loads only recent fixes.
Search here when a problem looks historically familiar.

- 2026-07-01: npm packages `treehouse`, `no-mistakes` are unrelated namesquats. Kun's real versions are Go tools installed via the repo `install.sh` or `go install`. Only `gnhf` and `gh-axi` are genuine on npm.
- 2026-07-04: nvim's `switch-theme` rewriting `active-theme.lua` never actually changed nvim's colors, because base46 only recompiles its cache on plugin (re)install, not when chadrc's theme value changes. Fixed in `init.lua` with a stamp-file comparison that forces `base46.load_all_highlights()` when the compiled theme differs from the requested one.
- 2026-07-04: this machine has `HOMEBREW_REQUIRE_TAP_TRUST` set, so any tap not explicitly trusted (`brew trust <tap>`) makes `brew bundle`/`brew bundle check` fail outright with "Refusing to load formula/cask from untrusted tap." If brew commands fail mysteriously, check this first before assuming the Brewfile is broken.
- 2026-07-04: upgrading the AeroSpace cask via brew while AeroSpace.app is running leaves the CLI talking to a stale server (protocol version mismatch, `aerospace reload-config` fails). Fix: quit and relaunch AeroSpace.app after any brew upgrade that touches it.
- 2026-07-04: `nvim-treesitter`'s `master` branch is frozen upstream (May 2025), officially supporting only up to Neovim 0.12 with no further fixes. On Neovim 0.12.3 this crashed on markdown files with HTML image blocks (`query_predicates.lua` calling `get_node_text` on a stale node during injection). Migrated `plugins/treesitter.lua` + `nvim-treesitter-textobjects` to the `main` branch, which is a full rewrite (no more `.configs` module; highlight/indent enabled via `vim.treesitter.start()`/`indentexpr` on `FileType`, textobjects via explicit keymaps). Do not revert to `master`.
- 2026-07-04: two external installers (an Airflow project setup, Antigravity IDE) append raw `export` lines to the end of `.zshrc`, after zoxide's init, which breaks zoxide's "init must be last" check and prints a warning on every shell start. If this recurs, move the appended lines into the "Third-party installer appends" section near the top of `shell/zsh/.zshrc`, above External Tool Init. `scripts/doctor` checks for this now.
- 2026-07-04: `image.nvim`'s built-in markdown integration only detects native `![alt](url)` image syntax, never raw HTML `<img>` tags (a very common README pattern for centered/sized images). This is true on every terminal, not a tmux/passthrough issue - `allow-passthrough` and Ghostty's Kitty-protocol support were both already fine. Fixed with a second custom integration at `nvim/.config/nvim/lua/image/integrations/markdown_html.lua` that walks the injected `html` tree directly. If images still don't render after this, the next thing to check is the terminal's actual Kitty graphics protocol support, not this detection layer.
- 2026-07-12: `shell/zsh/functions/` (sourced from `.zshrc`) defines a custom `open()` function that shadows `/usr/bin/open`. It only understands a single file-path argument (dispatches by extension to nvim/IINA/sioyek/etc.) and has no support for flag syntax at all — `open -a AppName` silently breaks with `zsh: no such file or directory: -a` because `-a` gets treated as a literal filename. Always use `/usr/bin/open -a AppName` (full path) when scripting an app launch/relaunch from this repo's zsh, or from any doc/fix-hint a user might paste into their interactive shell.
- 2026-07-12: `scripts/doctor` runs under `set -uo pipefail`. Piping a live command directly into `grep -q` (e.g. `some_cmd | grep -q pattern`) can FAIL the check even when the pattern matches, because `grep -q` closes its stdin pipe as soon as it finds a match, and the upstream command can then die from SIGPIPE — with `pipefail` that non-zero exit wins over grep's success. Fix: capture output into a variable first (`out="$(some_cmd)"; grep -q pattern <<<"$out"`) instead of piping directly, for any new doctor check that filters a command's live output.
- 2026-07-12: macOS `launchctl setenv FOO 1` only sets an env var for the current login session's launchd domain — it does NOT persist across reboots, and GUI apps (like Ollama.app) started via a Login Item never read `.zshrc`/`.zprofile` at all, so shell-rc-based exports can't reach them either. To make an env var persistently reach a GUI app across reboots, the only reliable mechanism is a LaunchAgent with `RunAtLoad` that itself runs `launchctl setenv` (see `launchd/com.dan.ollama-flash-attention.plist`, the first LaunchAgent in this repo, symlinked via the manifest like everything else). Note this only fixes *future* logins/launches of the target app — if the GUI app already started before the LaunchAgent's `setenv` runs, it won't pick up the new var until it's quit and relaunched.
- 2026-07-05: image.nvim images still don't visually appear in this config despite internal state/logs claiming success ("rendered", `is_rendered=true`). Hypothesized cause (unconfirmed, do not trust as fact): Neovim 0.11+ runs plugins in an `nvim --embed` server process where `io.popen("tty")` prints "not a tty", which image.nvim uses as its `editor_tty`; under tmux this could misroute clear/delete commands as raw unwrapped APC straight to the pane tty (forwarded late by tmux), landing after renders and wiping them. A fix attempt (`plugins/notebooks.lua`: `get_tty` patched via FFI `ttyname(1)`, `kitty_method = "unicode-placeholders"`, `window_overlap_clear_enabled = false`) looked correct in a scripted pty test but the user confirmed it is still not working live - so either the hypothesis is wrong or incomplete. The HTML-tag concealment from the entry above (`plugins/markdown.lua`) was reverted for now since hiding tags with no image behind them is worse than showing them; re-apply only once images actually render. Debugging lesson: image.nvim's internal "success" logging proves nothing about visibility - always get direct visual confirmation, ideally with a screenshot, before believing a fix worked.
